FUNCIONALIDAD 1: Inicio de Sesión


CASO 1 — Login exitoso con usuario estándar
-------------------------------------------
Lo que se quiere verificar es que un usuario con credenciales válidas pueda
ingresar al sistema sin problemas y llegar a la pantalla de productos.

Se ingresa el usuario "standard_user" con la contraseña "secret_sauce" y se
hace clic en Login. Se espera que el sistema redirija a la página de inventario
correctamente.

Resultado esperado: el usuario ve la lista de productos de Swag Labs.


CASO 2 — Login con contraseña incorrecta
-----------------------------------------
Acá se verifica que el sistema no permita el acceso cuando la contraseña es
incorrecta, y que además muestre un mensaje de error claro.

Se ingresa el usuario "standard_user" con una contraseña inventada y se hace
clic en Login. El sistema no debe redirigir al inventario.

Resultado esperado: aparece un mensaje indicando que las credenciales no son
válidas.


CASO 3 — Login con usuario bloqueado
--------------------------------------
Se verifica que un usuario que fue bloqueado administrativamente no pueda
acceder al sistema, aunque use la contraseña correcta.

Se ingresa el usuario "locked_out_user" con la contraseña "secret_sauce".
El sistema debe rechazar el acceso.

Resultado esperado: aparece un mensaje avisando que el usuario está bloqueado.


CASO 4 — Login con campos vacíos
----------------------------------
Se verifica que el sistema valide los campos obligatorios antes de intentar
hacer el login. No debería permitir enviar el formulario vacío.

Se deja el formulario completamente vacío y se hace clic en Login.

Resultado esperado: el sistema muestra un mensaje indicando que el campo
usuario es requerido.


CASO 5 — Login fallido intencionalmente
-----------------------------------------
Este caso está diseñado para fallar a propósito. Su objetivo es demostrar que
el framework captura una pantalla automáticamente cuando una prueba falla, y
que esa captura queda guardada en el reporte.

Se hace login correctamente y luego se verifica el título de la página contra
un valor que no existe.

Resultado esperado: el test falla, se genera una captura de pantalla y queda
registrado en el reporte HTML.



FUNCIONALIDAD 2: Carrito de Compras


CASO 6 — Agregar un producto al carrito
-----------------------------------------
Se verifica el flujo básico de agregar un producto: que el botón cambie de
estado, que el contador del carrito se actualice y que el producto aparezca
dentro del carrito al ir a verlo.

Se hace clic en "Add to cart" sobre el primer producto del inventario.

Resultado esperado: el badge del carrito muestra "1" y el producto aparece
listado al ingresar al carrito.


CASO 7 — Agregar múltiples productos al carrito
-------------------------------------------------
Se verifica que se pueden agregar varios productos al mismo tiempo y que el
contador del carrito refleja correctamente la cantidad total.

Se agregan tres productos distintos desde el inventario.

Resultado esperado: el badge del carrito muestra "3" y los tres productos
aparecen en la vista del carrito.


CASO 8 — Ver el contenido del carrito
---------------------------------------
Se verifica que los detalles del producto que se ven dentro del carrito son
correctos: que el nombre y el precio coincidan con lo que se mostró en el
inventario.

Se agrega el producto "Sauce Labs Backpack" y se navega al carrito.

Resultado esperado: el carrito muestra el producto con el nombre correcto y
el precio "$29.99".


CASO 9 — Eliminar un producto desde el inventario
---------------------------------------------------
Se verifica que un producto que ya fue agregado al carrito puede quitarse
directamente desde la pantalla del inventario usando el botón "Remove".

Se agrega un producto y luego se hace clic en "Remove" sobre ese mismo producto.

Resultado esperado: el botón vuelve a decir "Add to cart" y el badge del
carrito desaparece porque quedó vacío.


CASO 10 — Continuar comprando desde el carrito
------------------------------------------------
Se verifica que el botón "Continue Shopping" dentro del carrito funciona
correctamente y lleva al usuario de vuelta al inventario.

Se agrega un producto, se navega al carrito y se hace clic en "Continue Shopping".

Resultado esperado: el usuario regresa a la página de inventario sin perder
los productos que ya tenía en el carrito.
